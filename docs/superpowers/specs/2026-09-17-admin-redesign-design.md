# עיצוב מחדש של האדמין

תאריך: 17.09.2026  
סטטוס: תכנון לפני מימוש

## מטרה

להפוך את האדמין לכלי עבודה ברור לעורך ולמנהל נתונים: להבין מה דורש טיפול, להגיע לפעולה הנכונה, ולדעת מה פורסם ומאיזה מקור.

העיצוב מחדש אינו מחליף את מנגנוני הייבוא, המיזוג או ההרשאות. הוא מאחד את הניווט, שומר כתובות קיימות, ומעביר את הממשק בהדרגה כדי לא לסכן תהליכים תפעוליים.

## מבנה ניווט

מעטפת RTL משותפת לכל מסכי `/admin`, עם בחירת עונה קבועה, חיפוש וקישורי ניווט מקובצים:

| קבוצה | מסכים |
| --- | --- |
| סקירה | משימות שממתינות, כשלים, כיסוי נתונים, פעילות אחרונה |
| כדורגל | משחקים, קבוצות, שחקנים, מאמנים, שופטים ואצטדיונים |
| תוכן וארכיון | תיקי עונה, עמודי מועדון ותקופות, שירים, היכל תהילה, ארכיון אוהדים וחידונים |
| מקורות וסנכרון | API-Football, Sofascore, Flashscore, סריקות, ייבוא, מיזוגים ורענון לוח משחקים |
| מערכת | משתמשים, הרשאות, הגדרות אתר, התראות, העברת מסד נתונים |

הניווט הקיים נשאר פעיל. כל קישור עמוק ממשיך לעבוד; בשלב הראשון נוצרת מעטפת ורק אחר כך מסכים עוברים לתוכה.

## מסך סקירה

העמוד הראשי מציג ארבעה אזורים לפי עדיפות:

1. פעולות שדורשות טיפול: עבודת סריקה שנכשלה, מיזוג שממתין לאישור, פריט ארכיון שממתין לבדיקה, משחק קרוב שחסרים בו נתונים.
2. מצב נתונים לעונה שנבחרה: משחקים, הרכבים, אירועים, שחקנים ושורות טבלה עם זמן עדכון ומקור.
3. פעילות אחרונה: פרסום, עריכה, מיזוג ושינוי סטטוס, עם משתמש וזמן.
4. פעולות מהירות: יצירת משחק, פתיחת ייבוא, רענון לוח, עריכת תיק עונה ובדיקת ארכיון.

כל כרטיס מציג סטטוס, זמן עדכון וקישור לפתרון. אין כפתור הרסני ישירות במסך הסקירה.

## דפוסי עבודה אחידים

- טבלאות משתמשות בחיפוש, מסננים, עימוד ושמירת מסנן העונה בכתובת.
- עמוד עריכה מפריד בין שמירת טיוטה, שליחה לבדיקה ופרסום. סטטוס הפרסום מוצג תמיד.
- פעולות מיזוג מציגות preview, היקף השינוי, מקור ויכולת rollback לפני ביצוע.
- פעולות ארוכות מציגות התקדמות, לוג קריא, זמן התחלה וסיום ופעולה חוזרת בטוחה.
- פעולות שמוחקות, מפרסמות או מגלגלות לאחור דורשות מסך אישור שבו מופיע היעד המדויק.

## תוכן וארכיון

תיקי העונה, עמודי התקופות וארכיון האוהדים עובדים תחת אותו עיקרון: תוכן טיוטה אינו ציבורי, והעורך מפרסם במפורש. ארכיון אוהדים מוסיף תור בדיקה, קישורי מקור, קרדיט, הרשאת פרסום והיסטוריית תיקונים. אין להשתמש בתמונה, בטקסט או בקישור שנשלחו על ידי אוהד כעובדה סטטיסטית ללא אימות.

## הרשאות ואבטחה

העיצוב אינו מסתמך על הסתרת קישור. כל API ממשיך לבדוק הרשאת ADMIN בשרת. ממשקי קריאה אישיים נשארים מסוננים לבעלים. פעולות פרסום ומיזוג נרשמות בהיסטוריית פעילות. תצוגות מקדימות של תוכן טיוטה נגישות לעורכים בלבד.

## תכנית מעבר

1. להוסיף `AdminShell` וניווט קבוצתי בלי שינוי בדפי הנתונים.
2. להחליף את דף הסקירה בכרטיסי משימות ומצב נתונים, תוך שימוש בשאילתות הקיימות.
3. להעביר תחום אחד בכל פעם: תוכן וארכיון, כדורגל, סנכרון ולבסוף מערכת.
4. לבדוק מסלולים עמוקים, ניהול עונה, RTL ומובייל לפני כל מעבר.
5. למדוד זמן השלמת משימות ושגיאות תפעוליות לפני הסרת ניווט ישן.

## קריטריוני קבלה

- מנהל יכול להגיע לכל מסך קיים מהניווט החדש בלי לאבד כתובת או מסנן עונה.
- מסך הסקירה מכיל רק פעולות שיש להן נתון עדכני וקישור לפתרון.
- טיוטות, תוכן אוהדים והחלטות פרסום אינם נחשפים לציבור.
- מיזוגים ושינויים הרסניים שומרים את מנגנוני ה-preview וה-rollback הקיימים.
- כל מסך נוח ברוחב 390px ובמחשב, כולל מקלדת וקורא מסך.
