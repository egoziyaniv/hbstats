# Drive match photo import

User approved the following approach on 2026-10-31: inventory the owner's Hapoel Beer Sheva crowd and player photographs from Google Drive; preserve source and original capture date; import into existing MediaAsset game galleries only when a single HBS game matches the capture day in Israel. Uncertain records remain in a review list. Do not use Drive upload/modification timestamps as capture evidence.

Keep original files, private Drive identifiers, actual capture timestamps, preview images, the reviewed manifest and the old website backup private and outside Git. The private media bundle includes data/drive-photos/manifest.json and the image derivatives. Commit only an aggregate discovery report, documentation, tests and an idempotent, dry-run-by-default importer. Require explicit --apply to create gallery rows. Do not overwrite player portraits, existing gallery records, or primary images. Strip EXIF/GPS from published image derivatives. No schema or public UI changes are needed.

Read capture timestamps from EXIF DateTimeOriginal; dates without offsets are camera wall-clock dates, not UTC. Preserve after-midnight photographs for review rather than silently attaching them to the previous day's game. Use existing game IDs only after confirming the matching fixture. If a date has zero or multiple HBS fixtures, skip it and report the reason. A source hash prevents duplicate imports and detects missing/changed source images.

The legacy hbs-backup.gz was located in Drive's hbs site folder. It is 509,097,054 bytes; the connector refuses files exceeding 268,435,456 bytes, so it was downloaded through the authenticated browser. Only the site's gallery table and public image upload directory were inspected. Its 241 media files include charts, television captures, and credited editorial photographs, so they are held for source/date review rather than attributed to the owner automatically. The full hosting backup and its SQL remain private.
