**עמודות בגיליון "משחקים":**
- עונה, רמת ליגה, מסגרת, בית בגביע, שלב, מחזור/סיבוב, תאריך
- המשחק כפי שכתוב בספר, קבוצת בית/חוץ, תוצאה (בית:חוץ), הערה לתוצאה
- שערים לכל צד
- מבקיעים לכל צד, כולל דקה ופנדל
- מגרש, קהל, שופט, עמוד בספר

**איכות:**
- **שלמות:** תאריך ב-2,603 מתוך 2,610 שורות. שופט, קהל ומגרש מלאים כמעט לגמרי משנות ה-60 ואילך.
- **מבקיעים:** 1,733 מתוך 1,734 רשימות המבקיעים של באר שבע מסתכמות בדיוק במספר השערים.

**מלכודות שזוהו (חייבים לטפל בהן):**
- **סדר התוצאה בספר:** המספר הימני שייך לקבוצה הראשונה. משתמשים רק בעמודה "תוצאה (בית:חוץ)" ובעמודות השערים, לא בטקסט המקור.
- **"בפנדלים" (30 משחקים):** התוצאה הרשומה היא תוצאת הפנדלים, לא תוצאת המשחק. הם לא ייכנסו ל-`homeScore`/`awayScore` אלא רק ל-`homePenalty`/`awayPenalty`.

  - כתיב שונה משלנו: "פתח-תקוה" מול "פתח תקווה", "קרית" מול "קריית".
  - שגיאות הקלדה, למשל "מכביתל-אביב".
  - תוספות בסוגריים, למשל "הפועל צפת (ליגה א')".

## 3. עקרונות

1. **לא דורסים.** ממלאים רק שדה ריק. החריג היחיד הוא תאריך placeholder (1.9 בחצות UTC, או 1.5 ב-20:00), שמוחלף בתאריך אמיתי.
2. **לא מוחקים** שום נתון קיים.
3. **התנגשות = עצירה ודיווח.** אם התוצאה אצלנו שונה מהתוצאה בקובץ, לא נוגעים במשחק. הוא נכנס לדוח התנגשויות לבדיקה ידנית מול עמוד הספר.
4. **כל ערך שנכתב מתועד** עם המקור, הערך הקודם והערך החדש (סעיף 4). אפשר לבטל הכול, או אצווה אחת, בלי לפגוע בעריכות שנעשו אחר כך.
5. **הכול עובר דרך הרצה יבשה** עם דוח, ורק אחרי אישור רץ `--apply`.

## 4. תיעוד המקור וביטול (rollback)

ההנחיה הייתה שאם צריך לתקן, אפשר יהיה למחוק את כל מה שהגיע מהארכיון. לכן שלוש שכבות:

### 4.1 שכבת גלם: `ScrapedMatch` / `ScrapedMatchEvent`

- כל שורה בקובץ נשמרת כ-`ScrapedMatch` עם הערכים:
  - `source = 'eyal-archive'`;
  - `sourceId = 'p{עמוד}-{מס' שורה}'`, מזהה יציב;
  - `rawJson` עם השורה המלאה, כולל מספר העמוד בספר.
- המבקיעים נשמרים כ-`ScrapedMatchEvent`.
- זה תואם לזרימה הקיימת באתר: סריקה, ואז Scraped, ואז מיזוג.
- **ביטול השכבה:** `DELETE ... WHERE source='eyal-archive'`. הפעולה בטוחה, כי טבלאות הגלם לא מוצגות באתר.

### 4.2 יומן שינויים ברמת השדה: טבלה חדשה `data_import_changes`

```prisma
model DataImportChange {
  id        String   @id @default(cuid())
  source    String   // 'eyal-archive'
  batchId   String   // אצווה אחת = הרצה אחת של --apply
  table     String   // 'games' | 'game_events'
  recordId  String
  field     String   // 'dateTime' | 'refereeHe' | 'venueNameHe' | 'attendance' | '*created*' ...
  oldValue  Json?
  newValue  Json?
  basis     String   // 'direct' (משחק ב"ש) | 'round-inferred' (תאריך שהוסק מהמחזור)
  sourceRef String?  // 'p62-r300' — לחזור לשורה ולעמוד בספר
  createdAt DateTime @default(now())
  @@index([source, batchId])
  @@index([table, recordId])
  @@map("data_import_changes")
}
```

- **שדה נוסף ב-`GameEvent`:** `source String?`. אירועים שנוצרים מהארכיון מסומנים `eyal-archive`. כרגע אין לאירועים עמודת מקור, ובלעדיה אי אפשר להפריד אותם.
- **רשומה ב-`MergeOperation`:** כל אצווה מקבלת רשומה, כך שהיא מופיעה בהיסטוריית `/admin/merge`.

### 4.3 סקריפט ביטול: `scripts/eyal-archive/rollback.js`

- **הפעלה:** `--batch <id>` או `--all`, ובברירת מחדל הרצה יבשה.
- **שחזור:** כל שדה חוזר ל-`oldValue`, **רק אם הערך הנוכחי עדיין שווה ל-`newValue`.**
  - אם מישהו תיקן ידנית אחרי הייבוא, הסקריפט לא דורס את התיקון. הוא מדווח עליו.
  - זה אותו עיקרון שכבר קיים ב-`merge-rollback-safety.ts`.
- **אירועים:** מוחקים את האירועים שנוצרו (`source='eyal-archive'`). שיוכי שחקנים שנוספו להם נמחקים איתם.
- **נגזרות:** אחרי ביטול מריצים מחדש את החישובים הנגזרים, כלומר נתוני שחקן ותמונת עונה. אין טבלאות מצטברות לרענן מעבר לזה.

### 4.4 תצוגה

- **קרדיט במשחק:** משחק שקיבל נתון מהארכיון מקבל ב-`additionalInfo.sources` את הערך `["eyal-archive"]`.
- **קרדיט בדף:** דף המשחק מציג שורת קרדיט קטנה ("נתוני שופט, קהל ומבקיעים: הארכיון של אייל חטב"), אם החבר מאשר (סעיף 0).

### 5.2 מפתח ההתאמה למשחק

1. **התאמה מלאה:** עונה + מסגרת + קבוצת בית + קבוצת חוץ, ובליגה גם מחזור.
2. **התאמה בלי מחזור:** אם אין התאמה מלאה, עונה + מסגרת + בית + חוץ, בתנאי שיש בדיוק משחק אחד כזה.
3. **בדיקת תוצאה:** אם לשני הצדדים יש תוצאה, היא חייבת להיות זהה. במשחק "בפנדלים" משווים את התוצאה אצלנו לתיקו.
4. **אחרת:** אין התאמה, והשורה נכנסת לדוח עם סיבה. אף פעם לא מנחשים.

### 5.3 מה נכתב לכל משחק שהותאם (רק לשדה ריק)

| נתון בקובץ | שדה אצלנו | הערות |
|---|---|---|
| תאריך | `dateTime` | רק במקום placeholder. ראו "תאריך בלי שעה" בהמשך. |
| מחזור | `roundNameHe` | רק אם ריק ("מחזור 12") |
| שופט | `refereeHe` + `refereeId` | |
| מגרש | `venueNameHe` + `venueId` | |
| קהל | עמודה חדשה `attendance Int?` ב-`Game` | ראו החלטה ב' |
| בהארכה | `statusShort = 'AET'` | רק אם ריק |
| בפנדלים | `homePenalty` / `awayPenalty` | התוצאה הרגילה לא משתנה |
| טכני | `additionalInfo.resultNote` | התוצאה לא משתנה |
| שלב ("גמר-רגל עליון") | `additionalInfo.stage` | |
| מבקיעים | `GameEvent` (GOAL / PENALTY_GOAL / OWN_GOAL) | ראו פירוט בהמשך |

**תאריך בלי שעה:**
- לספר יש יום אבל לא שעת פתיחה. אם נשמור את התאריך בחצות, יוצג "00:00".
- **ההצעה:** נשמור משבצת קבועה, 10:00 UTC, ונרחיב את `src/lib/game-date.ts`. משחק בלי `apiFootballId` שיושב במשבצת הזו יוצג כתאריך בלי שעה ("23.12.1972").
- זה אותו מנגנון שכבר קיים ל-placeholder.

**מבקיעים:**
- נוצרים רק אם **אין** למשחק אף אירוע שער, ורק אם מספר המבקיעים שנקלט שווה לתוצאה. אחרת המשחק מדולג ומופיע בדוח.
- **פורמט:** "משה גורנס 40, חיים כהן 62". "2x" פירושו שני שערים בלי דקה. "77 פנדל" הוא PENALTY_GOAL.
- **מה נשמר:** השם נשמר ב-`participantName`, והקבוצה ב-`teamId`.
- **שיוך לשחקנים:** לאחר הכתיבה מריצים את `link-legacy-event-players.js` הקיים. הוא מקשר שם לשחקן רק בתוך הסגל של אותה עונה (כלל הבטיחות מ-`player-data-fragmentation`). שם שלא נמצא בסגל נשאר כטקסט, ומוצג באתר כך.

### 5.4 משחקים שאין להם התאמה אצלנו

- **סוגי המשחקים:** ליגה ברמות 2–4 בשנות ה-50–60 וה-90, ידידות, גביעים ישנים וחלק מאירופה לפני 2000. סך הכול כ-600–700 משחקים.
- **בשלב הזה הם לא נוצרים**, רק נכנסים לשכבת הגלם (4.1) ולדוח.
- **שלב 2 (החלטה נפרדת):** יצירתם מחייבת שורות `Season`/`Team`/`Competition` לליגות נמוכות. זה שינוי מבני בהיסטוריה של האתר, ומתאים לתכנון יחד עם גיליונות "טבלאות ליגה" ו"סיכום עונות".

## 6. השלמת התאריך לכל המחזור

הקובץ נותן תאריך רק למשחק של ב"ש. ההנחה היא שבאותה תקופה כל משחקי המחזור שוחקו באותו יום.

**מה הנתונים אומרים** (יום בשבוע של משחקי הליגה בקובץ):

| עשור | שבת | אחר |
|---|---|---|
| שנות ה-50 | 100% | – |
| שנות ה-60 | 97% | 7 באמצע שבוע (משחקים נדחים) |
| שנות ה-70 | 97% | 8 באמצע שבוע |
| שנות ה-80 | 97% | 6 בשישי, 3 אחרים |
| **שנות ה-90** | **75%** | **20% בשישי**: המחזור כבר התפצל לשישי ושבת |
| שנות ה-2000 | 59% | שישי, ראשון ושני |

**הכלל המוצע:**
- **עד עונת 1989/90:**
  - כל המשחקים במחזור שעדיין על placeholder (באותה עונה, מסגרת ומחזור) מקבלים את תאריך המשחק של ב"ש. התיעוד ביומן הוא `basis='round-inferred'`.
  - **חריג:** אם המשחק של ב"ש לא שוחק בשבת (משחק נדחה), לא מעתיקים את התאריך שלו לשאר המחזור.
- **1990/91 ואילך:**
  - ההצעה היא לכתוב תאריך רק למשחק של ב"ש. שאר המחזור נשאר עם "עונה · מחזור".
  - **החלופה (החלטה ג'):** לכתוב גם להם את תאריך ב"ש, עם סימון "תאריך משוער (סוף שבוע המחזור)".
- **בדיקות שפיות לפני כתיבה:**
  - התאריכים עולים ממחזור למחזור.
  - כל תאריך נמצא בטווח העונה.
  - אף משחק לא מקבל שני תאריכים שונים.
