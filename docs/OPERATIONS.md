## 1. משימות מתוזמנות (cron)

**מקור האמת הוא [`ops/crontab`](../ops/crontab) שבריפו** — ה-crontab החי על השרת אינו ב-git
ולא שורד בנייה מחדש של השרת. לעדכון:

```bash
# על השרת, אחרי git pull
scripts/install-crontab.sh          # מציג diff ומבקש אישור; --force לאוטומציה
```

הסקריפט מגבה את ה-crontab הקיים ל-`~/crontab-backups/` לפני כל החלפה.

השעות ב-**UTC** (ישראל היא UTC+3). זה קריטי: משחק ערב ישראלי ב-17:30 UTC הוא 20:30 מקומי,
ומשימה ב-01:15 UTC רצה ב-04:15 מקומי — כלומר **אחרי** משחקי אתמול ולפני משחקי היום.

| תדירות | משימה | תפקיד |
|---|---|---|
| כל 3 שעות | `refresh-fixture-schedule.js` | קורא מחדש שעות פתיחה + משלים תוצאות |
| כל 30 דק' | `matchday-live.js` | רענון כמעט-חי בחלון משחק (פתיחה −2ש' .. +5ש') |
| יומי 01:15 | `cron-matchday.sh` | היום + 3 ימים אחורה: תוצאות, אירועים, הרכבים, טבלאות |
| יומי 06:00 | `import-euro-fixtures.js`, `import-friendlies.js` | משחקי אירופה וידידות |
| שבועי | `sync-squads.js`, `scrape-sofascore-squads.js`, `backfill-sofascore-photos.js` | סגלים ותמונות |
| יומי 04:30 | `rebuild-records.ts` | שיאים ו"היום לפני" |
| יומי 02:00 | `backup-db.sh` | גיבוי DB |

לוגים: `/home/hbs/logs/`.

## 2. הבעיה שהכי קל לפספס: תאריכי משחקים ישנים

**זו הייתה הסיבה שמחזור שלם לא נאסף (ספטמבר 2026, תוקן ב-v0.37.3).**

רשימת המשחקים מיובאת חודשים מראש, כשההתאחדות פרסמה רק **תאריך** למחזור — ולכן כל 7 המשחקים
של מחזור נשמרים באותה שנייה בדיוק (כל מחזור 4 על `2026-09-14T17:00`). מאוחר יותר הליגה מפצלת
את המחזור בין שבת/ראשון/שני ל-16:45–17:30.

כל אוסף הנתונים מסתמך על שעת הפתיחה **השמורה אצלנו**:

- `matchday-live.js` פותח חלון סביב הפתיחה. במחזור 3 הוא פתח את החלון **בשבת** עבור 4 משחקים
  ששוחקו בשני, ועד יום שני כבר חשב שהם מזמן נגמרו.
- `cron-matchday.sh` בדק בעבר **רק את היום הנוכחי**, ורץ ב-01:15 — לפני שאף משחק של אותו יום
  התחיל. כלומר תוצאות של משחקי ערב לא נאספו לעולם.

התוצאה: תוצאות, אירועים, הרכבים וסטטיסטיקה פר-שחקן של מחזור שלם פשוט לא נאספו.

### סימני היכר לאבחון

- כל משחקי מחזור חולקים `dateTime` זהה לחלוטין.
- שורות שה-`createdAt` שלהן בן חודשים וה-`updatedAt` מעולם לא זז.
- השוואה בין מספר המשחקים שהחלון החי "ראה" לבין כמה באמת שוחקו באותו יום:

```bash
grep "fixture(s) in window" /home/hbs/logs/matchday-live.log | tail -20
```

ספירה **גבוהה מדי** ליום מסוים = משחקים עם תאריך שגוי. (בשבת 05/09 הלוג הראה
`7 fixture(s) in window` ביום שבו שוחקו רק 3 — ארבעת האחרים היו משחקי יום שני.)

### התיקון

`scripts/refresh-fixture-schedule.js` קורא מחדש את הלוח מ-API-Football בשני מעברים:

1. **רשימות הליגות** — ליגת העל (383) וליגה לאומית (382), קריאה אחת לכל ליגה.
2. **לפי מזהה** — כל שאר המשחקים שיש להם `apiFootballId` בחלון −7/+180 יום: ליגה אירופית,
   גביעים, ידידות. אלה יושבים מחוץ לרשימות הליגה ולכן המעבר הראשון לא רואה אותם כלל.

הוא גם משלים תוצאה של משחק שהסתיים ושלא נשמרה אצלנו — אבל **רק ממלא חוסר**: תוצאה שכבר יש
לנו לא נדרסת, כי IFA/FotMob מדויקים יותר.

```bash
node scripts/refresh-fixture-schedule.js --dry-run   # תכנון בלבד
node scripts/refresh-fixture-schedule.js             # ביצוע
```

> **מגבלה ידועה:** הסקריפט דורס את `Game.dateTime` מ-API-Football ללא תנאי, ולכן **תאריך
> שתוקן ידנית ב-`/admin/games` יוחזר תוך 3 שעות**. אין עדיין דגל שמגן על עריכה ידנית.
> בנוסף, המקור מפרסם את השעות האמיתיות רק ימים ספורים מראש — תאריך זמני שעדיין שגוי
> לא ניתן לתיקון מהמקור הזה בכלל.

## 3. "האתר לא התעדכן" — סדר בדיקות

```bash
# 1. האם המשחק בכלל קיים אצלנו, ומה התאריך והסטטוס שלו?
#    תאריך שגוי הוא ההסבר הנפוץ ביותר.
node scripts/refresh-fixture-schedule.js --dry-run

# 2. האם החלון החי נפתח בזמן הנכון?
grep "fixture(s) in window" /home/hbs/logs/matchday-live.log | tail

# 3. האם הסריקה הלילית רצה?
grep "matchday update" /home/hbs/logs/matchday.log | tail -3

# 4. איסוף ידני ליום מסוים
node scripts/matchday-update.js --date 2026-09-07 --league all --no-footystats --no-walla

# 5. טבלאות
node scripts/refetch_standings.js 2026 383
node scripts/refetch_standings.js 2026 382
```

### סטטיסטיקה פר-שחקן חסרה (FotMob)

נתוני FotMob — דירוגים, סטטיסטיקה פר-שחקן, xG, פצועים/מורחקים — נאספים **לפי קבוצה**,
ורק למשחקים שהחלון החי עבר עליהם. אם החלון לא נפתח (ראה §2), אין נתונים.

```bash
node scripts/scrape-fotmob.js --team 563 --season 2026     # קבוצה אחת
node scripts/scrape-fotmob.js --game <gameId> --match <fotmobMatchId>
```

מזהי FotMob של 14 קבוצות ליגת העל נמצאים ב-`AF_TO_FM` בתוך הסקריפט (ומשוכפלים ב-`FM_TEAMS`
ב-`matchday-live.js` — לשמור מסונכרנים). **ליגה לאומית לא ממופה** ולכן לא מקבלת נתוני FotMob.

## 4. תקינות נתוני שחקנים

הייבוא ההיסטורי (2009–2015) הותיר שלוש תקלות שגורמות לנתונים להיראות **שגויים** ולא חסרים —
ולכן קל לפספס אותן. כולן אובחנו ותוקנו בספטמבר 2026 עבור שחקני השירים; **שאר השחקנים באתר
עדיין נושאים את התקלה הראשונה**.

| # | תקלה | סקריפט |
|---|---|---|
| 1 | שורת שחקן נפרדת לכל עונה (`canonicalPlayerId = null`), כך ששחקן אחד הופיע כעד 15 אנשים שונים | `merge-chant-player-families.js` |
| 2 | אירועים לפני 2016 שמרו את שם הכובש כטקסט חופשי בלבד, בלי `playerId` — שערים נספרו לאף אחד | `link-legacy-event-players.js` |
| 3 | כפילות "שם הפוך": סגל החזיק גם "אליניב ברדה" וגם "ברדה אליניב"; ב-2014/15 הפיצול היה מוחלט — השורה ההפוכה החזיקה את השערים והרגילה את ההרכבים | `merge-reversed-name-duplicates.js` (+ `audit-reversed-name-duplicates.js` לבדיקה בלבד) |

הדגמה למה זה חשוב: אליניב ברדה הופיע עם **2 שערים ב-111 הופעות**. אחרי תיקונים 2 ו-3 — **35**.

### כלל הבטיחות

זהות שחקן נקבעת **רק** בתוך `teamId` יחיד (סגל אחד בעונה אחת), או מאימות ידני: רציפות מספר
חולצה, קו-זמן מועדונים שאינו חופף, ו-`nameEn`. **לעולם לא משם בלבד בין קבוצות** — לדור מלול
425 הופעות קריירה, רובן של הפועל חיפה, ומיזוג לפי שם היה מייחס אותן לבאר שבע בשקט.

לכן `merge-chant-player-families.js` עובד מול רשימת שמות שאומתה ידנית ומסרב לכל שם אחר,
ו-`merge-reversed-name-duplicates.js` מסרב למזג כששורש לא-נבחר כבר מחזיק משפחה משלו.

כל הסקריפטים כותבים רק `Player.canonicalPlayerId` ומצביעים של שירים/היכל תהילה — אף שורת
משחק, אירוע או הרכב לא נוגעים, ולכן המיזוג הפיך. כולם תומכים בהרצה יבשה ודורשים `--apply`.

### הצגה: תמיד בהקשר באר שבע

`src/lib/beer-sheva-spell.ts` מגביל כל מספר למשחקים **עבור המועדון** — לא לקריירה. קבוצות
באר שבע מזוהות לפי `nameHe` מדויק **וגם** `apiFootballId: 563`, כי שורות הקבוצה של 2001–2013
קדמו למזהי API-Football.

## 5. תמונות שחקנים ורישוי

תמונות מוויקישיתוף מאוחסנות עם ייחוס: `Player.photoCredit` ו-`Player.photoSourceUrl`.
הן ברישיון CC BY-SA, **שמחייב לציין יוצר ורישיון בכל מקום שהתמונה מוצגת** — ה-UI מרנדר את
הקרדיט ליד התמונה. אין להוסיף תמונה כזו בלי שלושת השדות.

```bash
node scripts/apply-commons-player-photos.js --dry-run
```

זיהוי מאומת מול היסטוריית המועדונים בערך בוויקיפדיה העברית — לא מהתאמת שם בלבד.
